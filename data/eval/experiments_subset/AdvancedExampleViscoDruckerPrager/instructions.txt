# Natural Language Specification for Visco Drucker-Prager Triaxial Driver Simulation

## Overview and Simulation Type

This simulation uses the Triaxial Driver solver in GEOS to perform a material point simulation of a triaxial compression test on a Visco Drucker-Prager solid. The Triaxial Driver is a specialized solver that tests constitutive model behavior without requiring a full mesh—it operates on a single material point under controlled triaxial stress/strain conditions. The purpose is to validate the Visco Drucker-Prager constitutive model implementation against semi-analytical solutions based on the Perzyna time-dependent viscoplasticity approach.

## XML File Structure

The configuration requires two XML files that work together:
1. A base file containing the constitutive material definitions
2. A driver-specific file containing the Task definitions for loading conditions

The files should be structured to allow the driver file to include or reference the base file.

## Solver Configuration

### Triaxial Driver Task

Create a Task block that defines the triaxial test protocol with the following specifications:

**Loading Protocol:**
- The test must include multiple loading and unloading periods in the axial direction
- Axial strain is imposed (strain-controlled in the axial direction)
- The imposed axial strain ranges must be large enough to induce visco-plastic yielding during both loading and unloading phases
- Lateral stress is held constant throughout the test (stress-controlled in lateral directions)

**Boundary Conditions for the Task:**
- Specify constant lateral confining stress (horizontal stress, σH)
- Define initial stress state for all three principal directions
- Reference table files that contain the time-history of imposed axial strain

**Time Stepping:**
- Define appropriate time increments (Δt) that work with the relaxation time of the material
- The time stepping must be fine enough to capture the viscoplastic response accurately

## Constitutive Model Specification

### Visco Drucker-Prager Material

Define a Visco Drucker-Prager constitutive model with the following parameters (all values must be specified in SI units):

**Elastic Properties:**
- Bulk modulus (K) in Pascals
- Shear modulus (μ) in Pascals
- Note: Young's modulus (E) is derived from these through standard elasticity relations

**Density:**
- Material density in kg/m³

**Viscoplastic Parameters:**
- Relaxation time (t*) in seconds - controls the rate-dependent viscoplastic response
- Viscosity parameter

**Drucker-Prager Yield Surface Parameters:**
- Frictional parameter (b) - defines the pressure dependence of the yield surface
- Initial cohesion parameter (a) in Pascals - defines the yield surface intercept

**Plastic Potential Parameters:**
- Dilation parameter (b') - controls the volumetric plastic strain direction (may differ from friction parameter for non-associated flow)

**Hardening Parameters:**
- Hardening rate (h) in Pascals - defines linear hardening behavior where cohesion evolves as Δa = h × Δλ

## Table File Requirements

Create table files in a designated tables directory that define:
- Time versus axial strain history showing loading and unloading cycles
- The strain values must be sufficient to cause yielding in both loading (positive shear stress q) and unloading (negative shear stress q) phases
- The sign convention follows compression as negative

## Mesh Requirements

The Triaxial Driver does not require a traditional mesh definition. It operates on a single material point with imposed triaxial boundary conditions. Therefore:
- No mesh block is needed
- No spatial discretization parameters are required
- No element type specification is necessary

## Initial Conditions

Specify initial stress state:
- Initial axial (vertical) stress σV
- Initial lateral (horizontal) stress σH
- These define the starting point before loading/unloading cycles begin

## Numerical Method Specifications

The Visco Drucker-Prager model in GEOS uses the Duvaut-Lions viscoplastic approach, which is equivalent to the Perzyna approach for linear hardening. Key numerical considerations:

- Time integration must be consistent with the relaxation time parameter
- The viscoplastic multiplier evolution follows: Δλ = (Δt/t*) × F/(3μ + Kbb' + h)
- Stress updates depend on whether yielding occurs at positive or negative shear stress

## Output Requirements

Configure output to write results to a text file named "ViscoDruckerPragerResults.txt" containing:
- Time history data
- Axial stress variation (Δσv)
- Lateral strain variation (Δεh)  
- Axial strain values
- Any internal state variables (plastic multiplier, cohesion evolution)

The output format should be suitable for post-processing with the provided Python validation script that compares GEOS results against the semi-analytical Perzyna-based solutions.

## File Organization

Organize the simulation files as follows:
- Main driver XML file at: inputFiles/triaxialDriver/triaxialDriver_ViscoDruckerPrager.xml
- Base constitutive model XML file at: inputFiles/triaxialDriver/triaxialDriver_base.xml
- Table files directory at: inputFiles/triaxialDriver/tables/

The driver XML file should include/reference the base file to access the constitutive model definitions while specifying the Task block with the specific loading protocol for this validation study.
