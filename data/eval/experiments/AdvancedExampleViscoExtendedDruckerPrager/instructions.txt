# Natural Language Specification for Visco Extended Drucker-Prager Triaxial Driver Simulation

## 1. Simulation Type and Physical Problem

This simulation uses the **Triaxial Driver** solver to perform a triaxial compression test validation study. The purpose is to verify the numerical convergence and accuracy of the Visco Extended Drucker-Prager constitutive model implementation in GEOS by comparing against semi-analytical solutions based on the Perzyna time-dependent viscoplasticity approach.

The physical scenario involves:
- A visco-elasto-plastic solid material subjected to triaxial compression
- Constant lateral confining stress maintained throughout the simulation
- Cyclic axial strain loading and unloading periods
- Strain magnitudes sufficient to induce plastic yielding during both loading and unloading phases
- Time-dependent viscoplastic behavior governed by the Duvaut-Lions approach

## 2. Solver Configuration

Create a **Triaxial Driver** solver configuration. This is a specialized material point driver solver that applies prescribed stress and strain conditions to test constitutive model behavior without requiring a full mesh-based simulation.

The solver should be configured to:
- Apply triaxial boundary conditions
- Handle time-dependent viscoplastic material response
- Track stress and strain evolution through loading/unloading cycles

## 3. Mesh Requirements

This is a **Triaxial Driver** simulation, which is a material point test rather than a full spatial discretization problem. No traditional mesh with dimensions, cell sizes, or element types is required. The driver operates on a single material point to test constitutive model behavior.

## 4. Material Properties and Constitutive Model

Configure a **Visco Extended Drucker-Prager** constitutive model with the following parameters (all values must be specified in SI units - International System of Units):

**Elastic Properties:**
- Bulk modulus (K)
- Shear modulus (μ)
- These define the elastic Young's modulus (E) and Poisson's ratio relationship

**Viscoplastic Properties:**
- Relaxation time (t*) - controls the rate-dependent viscoplastic response
- Frictional parameter (b) - defines the yield surface shape in stress space
- Dilation ratio (θ) - defines the plastic potential and volumetric plastic strain behavior
- Hardening parameters - for linear hardening law defining how the yield surface evolves with plastic strain

**Other Properties:**
- Density
- Viscosity

The model uses the Duvaut-Lions viscoplastic approach, which for linear hardening is equivalent to the Perzyna approach used in the semi-analytical verification.

## 5. Initial and Boundary Conditions

### Task Block Configuration

The Task block must define:

**Initial Stress State:**
- Specify the initial stress tensor components (initial confining pressure state)

**Lateral Confining Stress:**
- Define a constant lateral (horizontal) confining stress that remains fixed throughout the simulation

**Axial Strain History:**
- Define loading/unloading periods for the axial (vertical) strain
- The strain history should be specified through table files located in a tables subdirectory
- Strain values must be large enough to cause plastic yielding in both:
  - Loading phase (positive shear stress regime where q = -(σ_V - σ_H) is positive)
  - Unloading phase (negative shear stress regime)

**Time Stepping:**
- Define appropriate time increments (Δt) for the viscoplastic integration
- The time step interacts with the relaxation time to control viscoplastic strain rate

## 6. Numerical Method Specifications

The simulation employs:
- Time-dependent viscoplastic integration using the Duvaut-Lions approach
- The viscoplastic multiplier calculation involves the stress function F defining the yield surface
- Linear hardening law where the hardening rate h = (∂F/∂b)(∂b/∂λ)
- The numerical scheme must handle the transition between elastic and plastic regimes during loading and unloading

## 7. Output Requirements

Configure output to generate:
- A text file named **ViscoExtendedDruckerPragerResults.txt**
- The output should contain:
  - Axial stress variation (Δσ_V)
  - Lateral strain variation (Δε_H)
  - Axial strain values (Δε_V)
  - Time history of the loading/unloading cycles

The results will be post-processed using a Python script that compares GEOS numerical results against semi-analytical solutions.

## 8. File Structure

The configuration should be organized as:
- A base XML file containing the constitutive model definitions
- A problem-specific XML file containing the Task definitions (loading conditions, initial stress)
- Table files in a subdirectory containing the time-dependent loading history data

The problem-specific file should include/reference the base file to inherit the material model definitions while specifying the particular loading scenario.
