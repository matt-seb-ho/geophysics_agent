# Natural Language Specification for Drucker-Prager Triaxial Driver Validation Simulation

## 1. Simulation Type and Physical Problem

This simulation uses the **Triaxial Driver** solver to model an elasto-plastic triaxial compression test on a Drucker-Prager solid material. The purpose is to validate the numerical implementation of the Drucker-Prager constitutive model in GEOS against semi-analytical solutions.

The physical scenario involves:
- A material sample subjected to triaxial compression conditions
- Constant lateral (horizontal) confining stress applied throughout the test
- Cyclic axial (vertical) strain loading and unloading periods
- Strain magnitudes large enough to induce plastic yielding during both loading and unloading phases
- The simulation tracks the evolution of axial stress and lateral strain as the material undergoes elasto-plastic deformation

This is a single-element or material-point type simulation (driver test) rather than a full mesh-based simulation.

## 2. Solver Parameters and Settings

The solver type required is a **TriaxialDriver** (also called triaxial driver or material driver).

The Task block must specify:
- **Axial strain history**: Define loading and unloading strain periods as time-varying functions, likely referencing table files that prescribe the axial strain versus time or step
- **Lateral confining stress**: A constant value for the horizontal stress component that remains fixed throughout the simulation
- **Initial stress state**: The initial stress conditions in all principal directions before loading begins

The solver should be configured to:
- Handle the constitutive model integration for elasto-plastic behavior
- Track stress and strain components throughout the loading history
- Support both loading (increasing axial compression) and unloading (decreasing axial compression) phases

## 3. Mesh Requirements

This is a **Triaxial Driver simulation**, which means it operates as a single material point test rather than requiring a traditional spatial mesh. The triaxial driver simulates the constitutive response at a single integration point under prescribed strain/stress boundary conditions.

No mesh discretization, dimensions, or element types need to be specified. The driver internally handles the stress-strain computations for a representative material point.

## 4. Material Properties and Constitutive Model

The constitutive model required is **DruckerPrager** (Drucker-Prager elasto-plastic model).

The following material properties must be defined with values in **SI units** (International System of Units):

**Elastic Properties:**
- **Bulk modulus** (K): Specified in Pascals [Pa]
- **Shear modulus** (μ or G): Specified in Pascals [Pa]
- Alternatively, **Young's modulus** (E) and **Poisson's ratio** may be used

**Plastic/Yield Properties:**
- **Frictional parameter** (b): Dimensionless parameter controlling pressure sensitivity of yield surface
- **Dilation parameter** (b'): Dimensionless parameter controlling volumetric plastic flow
- **Hardening rate** (h): Rate of hardening/softening, specified in Pascals [Pa]
- **Initial cohesion** (a): Initial cohesive strength of the material in Pascals [Pa]

**Other Properties:**
- **Density**: Mass density in kg/m³

The Drucker-Prager model should be configured to handle:
- Pressure-dependent yield surface
- Non-associative flow rule (when dilation parameter differs from friction parameter)
- Hardening behavior based on accumulated plastic strain or work

## 5. Initial and Boundary Conditions

**Initial Conditions:**
- Initial stress state must be defined in the Task block, typically specifying the initial axial (vertical) stress and lateral (horizontal) stress components
- The initial state may be under some confining pressure before the strain loading history begins

**Boundary Conditions (Triaxial Test Conditions):**
- **Lateral/Horizontal stress**: Held constant at a specified confining stress value throughout the simulation
- **Axial/Vertical strain**: Prescribed as a time-varying function defined through table files
  - The strain history includes loading phases (increasing compressive strain)
  - The strain history includes unloading phases (decreasing compressive strain)
  - Strain magnitudes must be sufficient to cause plastic yielding in both directions

The table files (located in a tables subdirectory) should contain:
- Time or step values as the independent variable
- Corresponding axial strain values defining the loading/unloading protocol

## 6. Numerical Method Specifications

The Triaxial Driver uses an implicit stress integration algorithm for the Drucker-Prager constitutive model. Key numerical aspects include:

- Return mapping algorithm for plastic correction
- Consistent tangent operator for convergence
- The simulation validates numerical convergence and accuracy of the plasticity implementation

The driver should handle:
- Transition between elastic and plastic regimes
- Reversal of plastic flow direction during unloading
- Updates to the yield surface (cohesion parameter) as plastic deformation accumulates

No explicit time step or iteration parameters are typically needed as the driver steps through the prescribed strain history.

## 7. Output Requirements

**Output File:**
- Results must be written to a text file named **"DruckerPragerResults.txt"**

**Output Variables:**
The output should include (at minimum):
- Axial strain values (ε_V)
- Axial stress values (σ_V)
- Lateral/horizontal strain values (ε_H)
- Lateral/horizontal stress values (σ_H)
- Potentially: plastic strain components, cohesion evolution, or other internal state variables

The output format should be suitable for:
- Comparison with semi-analytical solutions
- Post-processing with the associated Python validation script
- Plotting stress-strain curves and strain paths

## 8. File Structure Requirements

The configuration should be organized across two XML files:
1. **Base file** (triaxialDriver_base.xml): Contains the constitutive model definitions including the Drucker-Prager material properties
2. **Driver-specific file** (triaxialDriver_DruckerPrager.xml): Contains the Task definitions including loading history, confining stress, and initial conditions; this file should include/reference the base file

Additionally, external **table files** in a tables subdirectory are needed to define the time-varying axial strain loading protocol.
