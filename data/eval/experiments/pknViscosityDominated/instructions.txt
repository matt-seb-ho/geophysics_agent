# Natural Language Specification for PKN Viscosity-Storage-Dominated Hydraulic Fracture Simulation

## Overview and Simulation Type

This specification describes a GEOS simulation for modeling the propagation of a Perkins-Kern-Nordgren (PKN) hydraulic fracture in a viscosity-storage-dominated regime. The simulation uses the hydrofracture solver to capture the coupled physics of fluid flow within the fracture, rock deformation, and fracture propagation. The model represents a quarter-scale symmetric geometry of a planar fracture that initiates and propagates from the center of a 20-meter-thick layer bounded by mechanical barriers. Plane strain deformation is assumed for the numerical model.

## Solver Configuration

### Primary Coupled Solver
Create a coupled hydrofracture solver that combines three elementary solvers for the multi-physics coupling between fluid flow, rock deformation, and fracture mechanics.

### Solid Mechanics Solver
Configure a SolidMechanicsLagrangianFEM solver with the following specifications:
- Target regions must include both the continuum rock region and the fracture region
- A contact relation name must be specified to define the contact constitutive behavior between fracture surfaces

### Flow Solver
Configure a SinglePhaseFVM solver for single-phase fluid flow within the fracture using the finite volume method.

### Surface Generator Solver
Configure a SurfaceGenerator solver with:
- Rock toughness value of 0.1e6 (equivalent to 0.1 MPa·√m) - this ultra-low value ensures viscosity-dominated propagation
- Node-based Stress Intensity Factor calculation enabled (nodeBasedSIF = 1) for the fracture propagation criterion

## Mesh Requirements

### Domain Geometry
Use the internal mesh generator to create a computational domain with dimensions:
- X-direction: 400 meters
- Y-direction: 400 meters  
- Z-direction: 800 meters

### Element Specifications
- Create a structured mesh with 105 × 105 × 60 elements in the x, y, and z directions respectively
- Use eight-node hexahedral brick elements (element type: C3D8)
- Group all elements into a single cell block named "cb1"
- Apply local mesh refinement in the vicinity of the fracture plane to capture fracture propagation accurately

### Fracture Plane Definition
Define a nodeset that occupies a small region within the computational domain where the fracture will initiate, open, and propagate upon fluid injection. This nodeset represents the fracture plane.

## Material Properties and Constitutive Models

### Rock Material
Use an ElasticIsotropic constitutive model named "rock" with the following properties (all values in SI units):
- Bulk Modulus (K): 20.0 GPa (20.0e9 Pa)
- Shear Modulus (G): 12.0 GPa (12.0e9 Pa)

### Fluid Properties
Use a CompressibleSinglePhaseFluid constitutive model named "water" with:
- Viscosity (μ): 1.0×10⁻³ Pa·s (equivalent to 1.0 centipoise)
- The fluid should be treated as essentially incompressible for storage-dominated behavior
- Density must be specified (used in mass flux calculations)

### Important Note on Domain Permeability
The domain should be configured as impermeable (no fluid leak-off) to satisfy viscosity-storage-dominated assumptions.

## Initial Conditions

The following fields must be initialized in the FieldSpecifications section:
1. **Water Density**: Initialize the fluid density field
2. **Separable Face**: Initialize the separable face field to define which surfaces can potentially separate
3. **Rupture State**: Initialize the rupture state of the propagating fracture elements

## Boundary Conditions

### Fluid Injection
Apply a mass injection rate (SourceFlux) at the surfaces of the initial fracture with:
- Scale value: -6.625 (negative indicates injection into the domain)
- This value represents Q₀ × ρf / 4, where:
  - Q₀ = 0.0265 m³/s (total volumetric injection rate)
  - The division by 4 accounts for the quarter-symmetry model
  - ρf is the fluid density

### Mechanical Boundary Conditions
Apply roller constraints (zero normal displacement) on all outer boundaries of the computational domain to prevent rigid body motion while allowing tangential movement.

## Time Stepping and Simulation Duration

- Total injection time: 200 seconds
- Configure appropriate time stepping through the Events section with periodic events for output and data collection

## Output and Data Collection Requirements

### Time History Collection Tasks
Define PackCollection tasks in the Tasks section to collect time history information from the fracture elements:

1. **pressureCollection**: Collect fluid pressure data
2. **apertureCollection**: Collect fracture aperture (width) data
3. **hydraulicApertureCollection**: Collect hydraulic aperture data
4. **areaCollection**: Collect fracture element area data

All these tasks should specify:
- Object path: "ElementRegions/Fracture/FractureSubRegion"

### Event Configuration
Create PeriodicEvent entries in the Events section to trigger the time history collection tasks at regular intervals during the simulation.

### Output File
Configure HDF5 output with filename "pknViscosityDominated_output" (will produce pknViscosityDominated_output.hdf5). This file should contain datasets for:
- Simulation time
- Fluid pressure
- Element aperture
- Hydraulic aperture
- Element area
