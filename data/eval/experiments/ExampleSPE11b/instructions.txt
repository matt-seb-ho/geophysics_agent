# Natural Language Specification for SPE11b CO2 Storage Simulation XML Configuration

## 1. Simulation Type and Physical Problem

This simulation models CO2 storage in a subsurface reservoir, specifically assessing residual and dissolution trapping mechanisms. The problem is based on the SPE11b benchmark (Nordbotten et al., 2024), which is a reservoir-scale 2D case derived from the FluidFlower experiment. The simulation uses a thermal compositional multiphase flow formulation to capture:

- Residual trapping of CO2 in heterogeneous multi-facies formations
- Dissolution trapping where CO2 dissolves into brine
- Convective mixing instabilities caused by density differences when CO2-saturated brine becomes heavier and sinks
- Thermal effects from injecting cold CO2 into a geothermally-heated reservoir

The domain represents a reservoir that is 8.4 kilometers wide and 1.2 kilometers deep, with the top of the reservoir located at 2 kilometers depth from the surface.

## 2. Solver Parameters and Settings

### Primary Solver
Configure a **CompositionalMultiphaseFVM** solver with the following settings:

- Enable the thermal formulation by setting the `isThermal` flag to true (value 1)
- Enable mass-based formulation by setting `useMass` flag to true (value 1)
- Configure `targetPhaseVolFractionChangeInTimeStep` parameter to control adaptive time stepping based on phase volume fraction changes
- Set `maxCompFractionChange` parameter to control solution chopping strategy within the nonlinear solver
- Define target regions corresponding to the reservoir facies

### Discretization
- Use **TwoPointFluxApproximation (TPFA)** for the finite volume discretization
- Apply the **Phase Potential Upwind (PPU)** scheme for flux calculations
- Link the discretization to the solver by name reference

### Nonlinear Solver Parameters
Configure nonlinear solver settings including:
- Nonlinear convergence tolerance
- Line search parameters
- Time step increase criteria
- Time step decrease/cutback criteria

### Linear Solver Parameters
- Use **Flexible GMRES (FGMRES)** as the iterative solver
- Apply **Multi Grid Reduction (MGR)** as the preconditioner

## 3. Mesh Requirements

### Domain Dimensions
- Width: 8.4 kilometers (8400 meters)
- Depth: 1.2 kilometers (1200 meters)
- This is a 2D simulation (reservoir cross-section)

### Discretization Resolution
The example uses a structured mesh with 840 cells in the horizontal direction and 120 cells in the vertical direction, giving:
- Horizontal cell size: 10 meters
- Vertical cell size: 10 meters

### Element Types
- Use hexahedral elements (referred to as hexahedra in region tags)
- The mesh should use VTI (structured/rectilinear) format

### Facies Regions
The mesh must define 7 distinct facies regions with different material properties. Additionally, buffer regions on the sides should be tagged as separate regions (identified as regions 12 through 15 in the hexahedra naming convention).

## 4. Material Properties and Constitutive Models

### Fluid Model
Use the **CO2BrinePhillipsThermalFluid** constitutive model for the two-phase CO2-brine system:
- CO2 density: modeled using **Span-Wagner** equation of state
- CO2 viscosity: modeled using **Fenghour** correlation
- Brine density and viscosity: modeled with appropriate pressure, temperature, and composition dependencies
- Include external table files for fluid property parameters

### Relative Permeability
- Define **tabulated relative permeability** curves for each of the 7 facies
- Use a TableRelativePermeability constitutive model
- Include water phase relative permeability and CO2 phase relative permeability tables
- Facies 5 requires particular attention as it plays a key role in trapping due to large property contrasts with adjacent layers

### Capillary Pressure
- Define **tabulated capillary pressure** curves for each of the 7 facies
- Use a TableCapillaryPressure constitutive model
- Include entry pressure values that vary significantly between facies (particularly the jump between facies 5 and upper layers)

### Rock Properties (Per Facies)
For each of the 7 facies, define:
- **Permeability**: constant value per facies, applied using field specification scaling
- **Porosity**: constant value per facies, applied using field specification scaling
- **Rock thermal conductivity**: constant value per facies, applied using field specification scaling (field name format: thermalCond_rockThermalConductivity where the prefix comes from the constitutive model name)

### Diffusivity
- Define a single constant diffusivity value (homogeneous across the domain)
- Specified directly in the constitutive model definition

## 5. Initial and Boundary Conditions

### Initial Conditions

#### Thermal Equilibration
- The simulation begins with a 1000-year thermal equilibration period (simulation starts at -1000 years in the event timeline)
- Apply a **geothermal gradient of 25°C per kilometer** depth
- Bottom surface temperature is **70°C**
- Use a Function to define the initial temperature distribution as a function of depth

#### Pressure Initialization
- Use **HydrostaticEquilibrium** initialization to compute initial pressure distribution consistent with the thermal gradient and fluid properties

#### Initial Composition
- Define initial fluid compositions using Functions
- Reservoir initially contains brine (water-rich phase) without free CO2

### Boundary Conditions

#### Temperature Boundaries
- **Top boundary**: Fixed temperature Dirichlet condition using FieldSpecification applied to a geometric set named "top"
- **Bottom boundary**: Fixed temperature Dirichlet condition (70°C) using FieldSpecification applied to a geometric set named "bottom"

#### Lateral Boundaries (Aquifer Buffers)
- Left and right boundaries use **fictive aquifer buffer zones** to damp pressure buildup during injection
- These buffers are implemented using source/sink terms applied to mesh regions tagged as "12_hexahedra" through "15_hexahedra"
- Volume scaling factors are applied to these buffer regions to achieve the desired aquifer response
- The scaling factor values depend on the mesh discretization and must be specified in the discretization-specific file

### Injection Conditions (Sources)

#### Source Definition
- Use **SourceFlux** elements (not wellbore models) to represent CO2 injection
- Two injection locations are required: a bottom injector and a top injector

#### Geometric Definition
- Define injection cell sets using Box geometry specifications
- Create named sets: "thermalSources1" for one injector and "thermalSources2" for the other

#### Injection Schedule
- **Bottom injector**: 50 years of continuous injection starting at time zero
- **Top injector**: 25 years of injection with a 25-year delayed start (starts at year 25, ends at year 50)
- Define injection rates using time-varying **TableFunction** with lower-interpolation (1D function over time)
- Rates are specified in **mass units** (consistent with useMass=1 flag)

#### Injection Temperature
- Apply **FieldSpecification** at injection locations to set the temperature of injected CO2 (cold CO2 injection)

## 6. Numerical Method Specifications

### Time Stepping
- All time values in GEOS are specified in **seconds**
- Total simulation duration: 2000 years (1000 years equilibration + 1000 years injection and post-injection)

### Event Structure
Define separate solver application events for different simulation phases with different maximum time step sizes:
1. **Equilibration phase**: From -1000 years to 0 years, allowing larger time steps
2. **Injection startup phase**: Around time zero when injection begins, requiring smaller time steps for stability
3. **Active injection phase**: 0 to 50 years with injection-appropriate time stepping
4. **Post-injection migration phase**: 50 to 1000 years (950 years of migration, dissolution, and convection)

### Functions
Define the following function types:
- **TableFunction** for injection flux schedules (1D, time-varying, lower-interpolated)
- **TableFunction** for initial geothermal gradient (depth-dependent)
- **TableFunction** for relative permeability and capillary pressure curves (saturation-dependent)

## 7. Output Requirements

### VTK Output
Configure output for visualization in Paraview:
- Write VTK files at regular time intervals
- Output should use multi-block VTK format

### Required Output Fields
- **Temperature** distribution
- **Phase saturations** (CO2 saturation, water saturation)
- **Dissolved CO2 fraction** in the brine phase (composition)
- **Pressure**

### Reporting
The benchmark defines three reporting boxes (A, B, and C) for monitoring:
- **Box A**: Located to observe initial CO2 accumulation in the first anticline and subsequent dissolution
- **Box B**: Located to observe CO2 accumulation at anticline tops due to migration through heterogeneous structures
- **Box C**: Located to observe development of convective mixing finger patterns

Define geometric boxes for these reporting regions to enable post-processing of integrated quantities.

### Key Output Times
- Results at 500 years post-injection start
- Results at 1000 years post-injection start (end of simulation)
- Time series data for mass balance calculations in reporting boxes

## 8. File Organization

The XML configuration should be organized as:
- **Main/root file**: Contains mesh-specific parameters, geometric definitions for injection boxes, buffer scaling factors, and event definitions (discretization-dependent)
- **Base parameter file**: Included by the main file, contains solver definitions, constitutive models, non-mesh-dependent field specifications, injection functions, and equilibration settings
- **Include files**: Separate files for relative permeability tables, capillary pressure tables, and property definitions that use field specification scaling
