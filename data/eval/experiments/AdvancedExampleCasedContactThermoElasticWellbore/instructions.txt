# Natural Language Specification for Cased ThermoElastic Wellbore with Imperfect Contact Interfaces

## Overview and Simulation Type

Create a GEOS XML configuration file for simulating a coupled Thermo-Hydro-Mechanical (THM) problem involving a cased wellbore with imperfect (debonding) contact interfaces. The physical scenario models cold CO2 injection causing temperature reduction at the casing surface. The simulation must allow for debonding (separation) at both the casing-cement and cement-rock interfaces.

The configuration should be split into two XML files: a base file containing the core solver definitions, material properties, and boundary conditions, and a benchmark file containing geometry specifications and interface definitions.

## Physical Problem Description

The wellbore system consists of three concentric layers:
1. Steel casing (innermost)
2. Cement sheath (middle)
3. Rock formation (outermost)

All three materials exhibit isotropic linear thermo-elastic behavior. Heat transfer occurs only through conduction (no convection or fluid flow). The problem is treated as an axisymmetric plane strain problem.

## Solver Configuration

Configure a coupled THM solver that handles imperfect contact interfaces. The solver requires:

1. **Primary Solver**: A coupled THM solver that combines thermal and solid mechanics solutions with contact mechanics
2. **Lagrangian Contact Solver**: For handling mechanical contact at the imperfect interfaces, allowing separation/debonding between layers
3. **THM Coupled Solver**: For solving the thermo-elastic coupling between temperature changes and mechanical deformation

The solver must be capable of tracking displacement jumps across contact interfaces and computing temperature-induced stresses.

## Mesh Requirements

Define a wellbore mesh with the following characteristics:
- Geometry: Cylindrical/axisymmetric representation of the wellbore
- Three distinct regions corresponding to casing, cement sheath, and rock formation
- Use Cylinder geometry objects to define nodesets for selecting the imperfect interface locations between:
  - Casing and cement (inner interface)
  - Cement and rock (outer interface)
- The mesh should be refined enough to capture the thermal and mechanical gradients near the interfaces

## Material Properties

### Solid Materials (Casing, Cement, Rock)
Define THM properties for three materials, all using isotropic linear thermo-elastic constitutive models:

1. **Steel Casing**: Define elastic modulus, Poisson's ratio, thermal expansion coefficient, thermal conductivity, and density appropriate for steel
2. **Cement Sheath**: Define elastic modulus, Poisson's ratio, thermal expansion coefficient, thermal conductivity, and density appropriate for wellbore cement
3. **Rock Formation**: Define elastic modulus, Poisson's ratio, thermal expansion coefficient, thermal conductivity, and density appropriate for the surrounding rock

### Contact Interface Properties
Define properties for the imperfect contact surfaces at both interfaces:

1. **Mechanical Contact Properties**: Specify contact stiffness and friction parameters for Lagrangian contact formulation
2. **Thermal Conductivity of Contact Interfaces**: Define thermal conductivity properties specifically for the contact interfaces to model heat transfer across potentially debonded surfaces
3. **Flow Properties for Contact Surfaces**: Although no actual flow is modeled, the fully coupled THM solver requires flow property definitions for the contact surfaces

### Surface Element Region
Define a surface element region that uses the contact interface properties, associating the thermal and mechanical properties with the interface elements.

## Initial Conditions

Specify in-situ initial conditions including:
- Initial temperature distribution throughout the domain (casing, cement, and rock)
- Initial stress state in all three materials
- Any required initial conditions for the contact interfaces

## Boundary Conditions

### Thermal Boundary Conditions
1. **Casing Inner Surface**: Apply a temperature reduction boundary condition representing cold CO2 injection (this is the driving force for the thermal problem)
2. **Far-field Boundary**: Apply appropriate far-field temperature boundary condition on the outer boundary of the rock formation domain

### Mechanical Boundary Conditions
1. **Casing Inner Surface**: Define any mechanical constraints or pressure conditions at the inner wellbore surface
2. **Far-field Boundary**: Apply far-field stress or displacement boundary conditions on the outer boundary
3. **Contact Surface Specifications**: Define contact boundary conditions that allow for debonding/separation at both the casing-cement and cement-rock interfaces

## Time Stepping and Numerical Parameters

Configure the simulation to run to a final time of 1e5 seconds (100,000 seconds). Include appropriate:
- Time step sizes for the coupled THM problem
- Nonlinear solver tolerances for contact convergence
- Linear solver parameters suitable for the coupled system

## Output Requirements

Configure outputs to capture:
1. **Displacement Jump**: Track displacement discontinuities across both the casing-cement and cement-rock interfaces
2. **Temperature Field**: Output temperature distribution throughout the wellbore system
3. **Radial Displacement**: Output the radial displacement field around the wellbore
4. **Stress Components**: Output total radial stress and hoop stress (tangential stress) components

Results should be available for comparison with analytical solutions at the final simulation time of 1e5 seconds.

## File Organization

The configuration should be organized as:
1. **Base XML File** (CasedThermoElasticWellbore_ImperfectInterfaces_base.xml): Contains solver definitions, material properties including contact thermal properties, contact flow properties, surface element region definitions, and boundary/initial conditions
2. **Benchmark XML File** (CasedThermoElasticWellbore_ImperfectInterfaces_benchmark.xml): Contains geometry and mesh definitions, interface nodeset selections using Cylinder geometry objects, and includes/references the base file

The benchmark file should include the base file to inherit all solver and material definitions while specifying the specific geometry for the validation problem.
