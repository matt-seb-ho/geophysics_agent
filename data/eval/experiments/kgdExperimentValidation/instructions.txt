# Natural Language Specification for KGD Hydraulic Fracture Validation Simulation

## Overview and Simulation Type

Create an XML configuration file for a coupled hydrofracture simulation that models a planar hydraulic fracture propagating in a finite domain. This simulation validates against the Rubin (1983) experimental benchmark of hydraulic fracturing in polymethylmethacrylate (PMMA). The problem involves viscous fluid injection creating a single planar fracture, with plane strain deformation assumed and zero fluid leak-off. Due to the vertical plane of symmetry, only half of the domain (one fracture wing) is modeled.

## Solver Configuration

### Primary Coupled Solver
Configure a main hydrofracture solver named "Hydrofracture" that couples three sub-solvers for the multi-physics problem involving fluid flow within the fracture, rock deformation, and fracture propagation.

### Sub-Solvers Required

1. **Solid Mechanics Solver**: Use a SolidMechanicsLagrangianFEM solver to model rock and fracture deformation. This solver must target both the continuum region and the fracture region. Specify a contact relation name for the contact constitutive behavior.

2. **Fluid Flow Solver**: Implement a SinglePhaseFVM solver to handle single-phase fluid flow inside the fracture using the finite volume method. Target the fracture region.

3. **Surface Generator**: Configure a SurfaceGenerator solver to define the fracture region and rock toughness. Set the node-based SIF parameter to 0 (nodeBasedSIF="0") to use edge-based Stress Intensity Factor calculation for the fracture propagation criterion. Specify the rock toughness value of 1.2 MPa·m^(1/2) (1.2e6 in SI units of Pa·m^0.5).

## Mesh Specifications

### Domain Geometry
- Total domain dimensions: 0.1525 m (x-direction) × 0.096 m (y-direction) × 0.055 m (z-direction)
- This represents half of the middle PMMA layer due to symmetry

### Mesh Discretization
- Use the internal mesh generator (InternalMesh)
- Number of elements: 80 elements in x-direction, 18 elements in y-direction, 10 elements in z-direction
- Element type: C3D8 (eight-node hexahedral brick elements)
- Cell block name: "cb1"
- Apply mesh refinement along the y-axis in the vicinity of the fracture plane

### Fracture Plane Definition
Define a nodeset that occupies a small region within the computational domain where the fracture will open and propagate upon fluid injection. This nodeset defines the initial fracture location and potential propagation path.

## Material Properties and Constitutive Models

### Rock Properties
Use an ElasticIsotropic constitutive model for the rock material named "rock" with the following properties:
- Bulk Modulus: 4.11 GPa (4.11e9 Pa)
- Shear Modulus: 1.2 GPa (1.2e9 Pa)
- Assume homogeneous and isotropic material properties throughout the domain

### Fluid Properties
Use a CompressibleSinglePhaseFluid model for water with:
- Fluid Viscosity: 97.7 Pa·s
- Appropriate density for water (required for mass injection rate calculation)

All constitutive parameters must be specified in SI units (International System of Units).

## Initial Conditions

Initialize the following fields:
1. **Water Density**: Set initial fluid density in the domain
2. **Separable Face**: Initialize the separable face field for potential fracture surfaces
3. **Rupture State**: Initialize the rupture state for the propagating fracture elements

## Boundary Conditions

### Fluid Injection
Apply a mass flux boundary condition (SourceFlux) at the surfaces of the initial fracture:
- Scale value: -0.0000366 (representing Q₀ × ρ_f / 2, where Q₀ = 73.2×10⁻⁹ m³/s)
- The negative sign follows GEOS convention
- Only half the injection rate is specified because the symmetric half-domain is modeled
- Injection duration: 100 seconds

### Mechanical Boundary Conditions
1. **Traction-Free Surfaces**: Apply zero traction (traction-free) boundary conditions on lateral surfaces named "xpos", "ypos", and "yneg"
2. **Roller Constraints**: Apply roller constraints (zero normal displacement) on all remaining outer boundary surfaces
3. Note: Compressive stresses use negative sign convention in GEOS

## Numerical Method Specifications

- Use edge-based Stress Intensity Factor (SIF) calculation for fracture propagation criterion (not node-based)
- Finite volume method for fluid flow discretization
- Lagrangian finite element method for solid mechanics
- Structured mesh with hexahedral elements

## Output and Time History Requirements

### Time History Collection Tasks
Configure PackCollection tasks for the following field data collection from the fracture element subregion (object path: "ElementRegions/Fracture/FractureSubRegion"):
1. **pressureCollection**: Collect fluid pressure time history
2. **apertureCollection**: Collect element aperture time history
3. **hydraulicApertureCollection**: Collect hydraulic aperture time history
4. **areaCollection**: Collect element area time history

### Events and Output
- Define a PeriodicEvent to trigger the collection tasks at regular intervals
- Output file format: HDF5
- Output filename: "KGD_validation_output.hdf5"
- The output file should contain datasets for: simulation time, fluid pressure, element aperture, hydraulic aperture, and element area for the propagating hydraulic fracture

## File Structure Notes

The configuration should be split into two XML files:
1. A base configuration file containing solver definitions, constitutive models, boundary conditions, and task definitions
2. A benchmark-specific file containing mesh specifications and fracture plane nodeset definitions that can include or reference the base file
